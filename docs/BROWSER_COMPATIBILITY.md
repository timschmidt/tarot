## Real Firefox baseline

The phone already has Firefox ESR 140.12.0-r0 and mobile-config-firefox 5.4.1-r0. The fixture launches the actual installed executable as the ordinary login user, with a separate profile/HOME/XDG directories and a loopback HTTP site. `--profile` and `--no-remote` select that isolated instance. Startup preferences suppress first-run/default-browser pages; the browser sandbox is retained. [Mozilla command-line documentation](https://firefox-source-docs.mozilla.org/browser/CommandLineParameters.html).

The revision-25 native inspection reproduces a rendering/input mismatch: tapping the rendered Text field focuses the Private field. Actual browser-side DOM events confirm the wrong target. The protocol trace shows a 720×1304 EGL/DMABUF buffer on a separate desynchronized surface, while Tarot does not advertise `wp_viewporter`. Mozilla's ESR-140 surface code creates a viewport through that global when available. Revision 26 advertises that standard capability and the native field receives the intended tap and text. [Inspected Mozilla source](https://github.com/mozilla-firefox/firefox/blob/esr140/widget/gtk/WaylandSurface.cpp).

Both original inspections, exact sources, browser/profile logs and captures are preserved under ignored `artifacts/m2/browser-r25/`. Each controller restores original preferences, removes its temporary desktop entry and returns the phone to normal Tarot. No package change occurs between the two baseline inspections.

## Standard surface viewports and parent commits

Tarot now initializes/delegates Smithay's standard `wp_viewporter` implementation. Its double-buffered crop/destination state is validated by the existing buffer-commit handler and used by the renderer's surface view. No per-browser buffer-scale inheritance is introduced.

The new real-protocol regression uses independently colored SHM regions to check root and subsurface source crops, destination scaling, local input coordinates, source/destination commits without new buffers, viewport destruction and malformed-client isolation. It also changes a viewport while protected, requires diagnostic redaction and verifies the new pixels only after valid unlock. Duplicate viewport and out-of-bounds source requests disconnect only their offending clients.

That regression first exposes a separate pinned-Smithay defect: a desynchronized child remains at its old position after a parent-only commit. This matches upstream issue #1894. The local three-file adaptation of proposal #2141 at `e96548206bdb134c272ec302cb1e0f32fa580836` stages positions in parent transaction state, avoids stale child snapshots and applies all transaction state before callbacks. The proposal is unmerged; it is recorded separately from the existing damage backport and session-protection patch. [Issue](https://github.com/Smithay/smithay/issues/1894), [proposal](https://github.com/Smithay/smithay/pull/2141), [local attribution](../third-party/README.md).

The delayed-parent transaction test passes through Smithay's public server/client API, including a blocker and desync-to-sync transition, with a bounded deadline. Both scale-1/2 pixel/input replays pass. All 146 ordinary tests pass on current/minimum compilers, strict host/ARM checks pass, and existing lifecycle/transient, rounded cards, stacks, launcher, editor, terminal, helper-crash, lock/idle and rotation regressions pass. The three-file proposal patch independently applies to the published 0.7.0 source and matches the vendored files.

## Revision 28 observer diagnosis

Focused trials use the unchanged installed revision-28 package. A failing post-PAM check receives `commit_string` and `done` in the browser, enters Firefox's commit handler, and reports no recognized IME failure. Its last DOM snapshot predates unlock. A later bounded-HTTP trial captures the expected `tarotxz` visibly in the field while the observer still reports `tarotx`; the final snapshot is approximately 17.3 seconds old. That failure cannot establish a dropped character. An earlier fully passing focused trial remains separate from these failures. Full native acceptance remains open.

The observer now includes document/window focus, visibility, composition flags, numeric selection bounds and report age. Diagnostic states append finite synthetic alternatives without changing historical indices or accepting alternatives to the expected text. `--protocol-metadata` records text-input methods/serials and keyboard surface enter/leave identities; it discards string arguments, key codes and held-key arrays. `--ime-metadata` filters only the isolated synthetic Firefox child's `IMEHandler` stderr into fixed method/status/reason metadata. Raw commit/selection text and unrecognized stderr are discarded before persistence. Login and locker logging are unaffected.

The inspected [GTK 3 Wayland input module](https://raw.githubusercontent.com/GNOME/gtk/gtk-3-24/modules/input/imwayland.c) applies pending commits during `done`; serial mismatch alone does not establish a lost GTK commit. The [Mozilla ESR-140 IME wrapper](https://raw.githubusercontent.com/mozilla-firefox/firefox/esr140/widget/gtk/IMContextWrapper.cpp) identifies commit/focus handlers and their failure messages for the strict filter. These are branch-source references, not a claim of exact source equivalence to the installed Alpine build. Earlier successful queued `caf` delivery also contains two `done(0)` events, so changing server serial validation is not justified by these traces.

HTTP reports now abort after three seconds and count failed delivery before advancing the queue. The bounded trial counts three failures but still lacks fresh post-key snapshots. The default WebSocket observer avoids waiting for a fetch response between snapshots; `--report-transport http` retains the comparison path. It uses one same-origin loopback connection, preserves event order, coalesces queued heartbeats, reconnects after closure, and caps each validated text message at 8192 bytes. Both transports feed the same field allowlist and exact-value assertions. The small QA receiver implements masked/fragmented text, ping/pong and close framing from [RFC 6455](https://www.rfc-editor.org/rfc/rfc6455); it adds no Tarot runtime dependency.

The first WebSocket trial passes the entire focused browser case, including actual PAM, password/history/popup and fullscreen Unicode entry. It records 116 heartbeats, a maximum reported closure/reconnect counter of one and a maximum report delay of 1118.8 ms. A fresh trial with protocol/IME diagnostics disabled fails earlier: the overview-return `x` does not appear in fresh DOM snapshots. Its final primary state remains `tarot`, document focus is true, the final report is only 366.4 ms old, and reported transport failures are zero. The passing trial does not close this separate native-input failure. The next investigation should correlate trusted-helper touch/frame/activation boundaries with browser commit delivery across overview/field changes, using fixed metadata and retaining the security teardown behavior.

All sixteen host observer checks pass; the phone passes thirteen and skips three optional Node producer checks. Six focused controllers preserve their original outputs and executed sources; each has independent normal-session and Panfrost cleanup audits. All 335 frozen Rust files and the installed revision-28 payloads remain unchanged. [Curated comparison evidence and unmodified capture](recordings/r28/README.md#browser-observer-follow-up) distinguish these QA changes from the earlier favorite component checkpoint.

Input is still delivered through the native keyboard. The 15-second exact-text deadline, input timing, PAM boundaries and browser sandbox remain unchanged. Observer transport comparisons do not establish a production IME fix. Preserve original failures, inspect source timestamps before treating an old value as a DOM mismatch, and require fresh observations in subsequent browser and complete native replays.

## Revision 31 keyboard delivery checkpoint

Native revision-29/revision-30 comparison proves keyboard layer teardown canceled an app-owned touch; the corrected teardown consults the seat's actual implicit grab owner. Revision 30 then passes 21 exact-text card-return cycles but drops the first fullscreen character because a newly committed keyboard is hit-testable before its rendered placement is cached. A real Wayland test reproduces that coordinate gap without a renderer. Revision 31 adds a fallback only for the visible registered keyboard's committed subtree, preserving app/card presentation transforms.

The signed revision-31 focused replay passes all five touch-ownership cases and the complete focused browser sequence, including queued taps, 21 card returns, real PAM, masked password, navigation/history, popup input/close and fullscreen Unicode entry. Its observer reports zero transport failures and its helper emits no missing-placement warnings. The subsequent broader run fails before completing its first card-return cycle: the page field blurs after enable/remap, and the keyboard deactivates. Fresh DOM observations, painted target pixels, configure/focus timing, original sources and independent normal-session/Panfrost audits are retained. This remaining failure is not established as either an observer fault or a specific production cause. [Exact comparison and limits](recordings/r31/README.md).
