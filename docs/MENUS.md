# App and device menus

Revision 39 is installed. Its initial menus pass in a 14-component native shell run; a separate focused Launcher-page and saved-restart replay passes on the same binaries. Independent restoration/normal-session/Panfrost audits pass after both controllers. [Evidence, retained recognition failure and limits](recordings/r39/README.md). [Delivery plan and native export research](MENUS_PLAN.md).

The left title opens the current activity menu. The right status area opens the device menu. Repeated activation closes the same root; activating the other anchor switches roots. Menus overlay the current activity with Nocturne's dark gradient, rounded border, shadow, pale typography and separators. The starting widths are 236 logical units for activity commands, 250 for the device root and at most 440 for detail pages. All widths and scroll areas are constrained to the output and available height above the gesture strip or credential keyboard. Rows start at 56 units and grow for wrapped text.

The device root displays the actual local date, observed battery and Wi-Fi/sound summaries. It opens the existing Wi-Fi, sound and power/display pages, Notifications and available locking. Its brightness slider commits on release, shows the observed value and preserves the existing asynchronous pending/error behavior. Drawing or opening a menu never requests a brightness change. Unsupported controls stay unavailable. Bluetooth and airplane mode remain future service work.

Activity commands reflect the current shell view. Launcher commands open search, start page naming, organize favorites or enter the page hierarchy. Page commands open, rename, reorder or remove the selected stable page identity; the final page cannot be removed. Just Type offers Clear search and Close. Card View offers card activation, cooperative close and the existing stack/placement actions. Ordinary native apps show an explicit **Card controls** caption with Show cards and Close card. Native app content and internal commands remain owned by the app. No illustrative mail command is exposed without an actual capability.

Every opening, root/submenu change or relevant client change retires the previous menu revision. Commands carry that revision and a typed target, and are checked against the current enabled items before dispatch. Brightness additionally requires the current service generation, writable capability, valid 5–100% range and no pending change. Detail-page widgets include their service generation in their identity. A held row or slider cannot activate a replacement after its identity changes.

Opening retires underlying text focus and card/icon gestures. Outside contact dismisses and is consumed. Escape/Back returns through submenus before dismissing the root. Arrow keys select enabled rows; Enter activates an explicit selection. Existing credential Escape/Enter handling takes precedence. Dismissal restores eligible search/name input or the same surviving native owner. An activity owner's death dismisses its menu. A device menu remains usable if the underlying app exits, but dismissal does not focus the replacement app. Protection discards menu state and restoration eligibility.

Host checks include model lifetime/credential/page/brightness contracts and actual egui press/release tests for stale rows, consumed outside contact, passive drawing and brightness drags across service replacement. The rendered replay uses private X/Wayland sessions, screenshots, OCR-selected visible menu rows, actual keyboard input, and accepting/refusing native clients. The Launcher replay follows the new page hierarchy while preserving its original exact settings and saved-restart assertions. Native checks also verify service changes through sysfs/libpulse, ordinary-user touch/rotation/PAM, accepting/refusing clients and client death. A header-bounded attached-chevron recognition correction resolves the retained page QA failure at unchanged confidence; the original failing controller stays separate from the subsequent focused passing replay.

Menu descent/closing motion, brightness-rail contrast and compact service glyphs, enlarged text calibration, packet G physical/visual approval, GTK/KDE exported app actions and the cooperating Rust app spike remain open. These menus do not close the retained browser input failures, notification composition, device endurance or any unfinished M0–M6 milestone.
