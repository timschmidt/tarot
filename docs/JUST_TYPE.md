## Entry and navigation

Tap the Just type affordance in Home/Card view, begin typing on an attached keyboard there or in Launcher, or choose Search applications in the Launcher menu. Search is a distinct light sheet inside the Launcher activity, with the shared shell keyboard above the gesture strip. Its origin is retained independently of named page settings. Closing Just Type returns to that origin; an empty previous Card view becomes Home if its last card disappeared. Navigation/focus changes retire old search choices. The original Launcher page arrangement and Quick Launch identities remain independent.

The field has an explicit clear control that retains focus. Hide dismisses the keyboard while preserving the query; tapping the field reopens it. Escape closes an open menu before leaving search. A Just Type menu provides Clear search and Close Just Type. Settings/dashboard interruption preserves the query and removes its keyboard until the field is focused again. The existing protected compositor boundary hides ordinary content/input during lock and real PAM; a retained query is not authentication input.

## Actual result sources

| Group | Matching and selection |
| --- | --- |
| Applications | All query words match case-insensitively across the installed name, comment and keywords. Select to focus an existing matching card or launch the desktop entry. Unavailable entries retain their real launch explanation. Search tiles retain hold-and-drag Quick Launch organization. |
| Settings | Wi-Fi, Sound, Rotation & idle lock, Notifications and Power open the existing corresponding controls. Common aliases include wifi/wlan, mute, rotate/brightness, dnd and charging. Backend unavailability remains visible in those controls. |
| Notifications | Retained notification snapshots are local content. Private-preview policy excludes summary/body from matching and presentation. Default actions use the exact notification ID/revision; entries without a usable default action open the dashboard and scroll to that exact retained entry. Replacement and orphan/lifetime policy remain authoritative. |
| Actions | A well-formed explicit HTTP(S) address can open in the default browser. Embedded credentials and non-web schemes are rejected. |
| Search using | Selecting DuckDuckGo sends the query as one encoded URL parameter to the default browser. Text entry does not start network queries. |

An empty query shows available settings rather than fictional content. Those empty-query controls currently require pointer/touch activation; accepting an explicitly selected one with Enter remains follow-up keyboard work. Unicode text is retained; matching currently uses lowercase words without stemming, accent folding or language-specific ranking. The query is limited to 1,024 characters / 4,096 UTF-8 bytes and rejects control characters. It is runtime state, not a preference/history record.

Up/Down select a result and scroll it into view. Enter can accept the first local result; it never implicitly submits an unselected external provider. Explicit arrow selection followed by Enter can accept a provider. Every choice carries a query revision and stable target identity; membership is revalidated before effects. Changing a query away and back cannot revive a held old choice. Notification targets also retain the notification revision. New-query rows use new egui identities. Revision 38 adds a separate selection revision, allowing each validated selection of the same notification to request a new dashboard scroll. A single UI token remembers that request; it does not continuously override manual scrolling.

Portrait uses grouped bands and three-column application results. With the keyboard visible in landscape, the first group omits its leading band and uses a full 56-unit touch row; compact app labels use one line. Result scrolling stays above the keyboard/gesture strip. The application grid renders only visible rows. The compact dashboard places its controls in two rows so a selected notification remains readable. The fallback-content replay requires the buried record to appear in dashboard-only rendered OCR, excluding the dimmed search result behind the panel. A matching diagnostic ID alone is insufficient. Reselection after actual manual scrolling must reveal the same record again. Physical calibration, text enlargement and complete accessibility acceptance remain separate gates.

## Explicit URI handoff

Tarot-owned code remains Rust. One worker with a one-request pending queue performs standard Linux default-browser handoff; it never blocks compositor evaluation on URI helpers. `xdg-mime query default` identifies the selected HTTP/HTTPS desktop handler, and `gio open` receives the URI as one argument. The helpers use the selected Tarot Wayland/session environment. Queries are encoded with locked Rust `url` 2.5.8, already present in the dependency set. No shell command is constructed from text. Helper stdout/stderr is discarded; user feedback contains no submitted query. Duplicate pending browser activations are suppressed and provider controls show their pending state.

The MIME query has a three-second deadline and a 4,096-byte output bound; the opener has a ten-second deadline. A successful handoff is not proof that a page loaded or a new window opened. If the default handler has an already mapped matching card, a still-current search can focus it; a stale completion or protected/modal session cannot take focus. Other launch outcomes retain recoverable feedback. The Nura package declares GLib and xdg-utils. [Default handler query](https://portland.freedesktop.org/doc/xdg-mime.html) · [GIO default-URI behavior](https://docs.gtk.org/gio/type_func.AppInfo.launch_default_for_uri.html).

The private rendered replay uses its own X display, D-Bus session, XDG directories, MIME defaults, real notification sender and native app. Its URI handler accepts only finite synthetic examples through a local Unix socket and performs no web request. It verifies actual input, Unicode preservation, local/default notification actions, existing-card focus, explicit GIO invocation and unchanged preferences. It does not establish phone KMS/PAM or real-site/browser reliability.
