# Revision 20 native popup overflow checkpoint

These are unmodified captures of synthetic diagnostic clients. [Exact package, binary, source, executed-QA and image identities](evidence.json) distinguish the actual PinePhone Pro/Panfrost/KMS frames from the host failure.

- [GTK3 menu](gtk-popup.png): the actual touch selects **Hotel** at physical pixel (177.5, 1266), beyond the conservative dialog bound ending at y=1065. The widget reports Hotel.
- [Qt6 menu](qt-popup.png): the actual touch selects **Golf** at (158.5, 837.5), beyond the conservative bound ending at y=736. The widget reports Golf. The keyboard remains open, matching Qt's real input-panel behavior.
- [Native protocol overflow](protocol-overflow.png): a blue popup extends beyond its small red dialog over the green parent. Its intentionally oversized buffer also stresses the family-card clip. The four-orientation test checks pixels, actual client-received touch/key coordinates and rounded outer clipping independently.
- [Revision-19 host failure](host-before-overflow.png): the same protocol fixture finds green parent pixels where the blue popup should be. This is a nested-backend capture, separate from the native frames above.

Each toolkit bound uses the real dialog allocation centered in the card plus ten logical pixels on every side. GTK reports 332×329; Qt reports 280×240. Toolkit allocation includes its own layout/decorations and does not specify xdg window geometry. A recognized menu item must lie beyond the conservative bound, have at least 80% OCR confidence and produce the exact corresponding widget event. Cancel and Apply also require exact native-keyboard text and a natural dialog height.

The renderer preserves each native window's Fit/CENTER transform but clips its surface tree at the family card rather than the dialog target. Rendering and inverse input share the exact rounded offset. The existing rounded/rotated mask and final output crop remain. Element parity checks compare geometry, source, opacity, opaque regions and damage with pinned Smithay at both scales; no vendored patch is added.

The first native attempt passes all four protocol cases and GTK, then captures Qt during asynchronous keyboard reopening: the target app height is 412 while its drawn height is still 463.83. The corrected QA waits for final geometry to remain stable for 350 ms before capture; both toolkits then pass. The fresh controller verifies identical loaded payloads before reusing only the earlier passing protocol evidence. It does not reinstall or change the product package.
