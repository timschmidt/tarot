# Named Launcher pages

This implements the named-page interaction in the owner's original [design packet](Tarot_Design_Packet/source/build_packet.py), especially screen 03. Signed revision 34 now passes the scoped native Launcher component and saved restart. The owner qualitatively confirms page/control usability on the phone. Calibrated physical-panel conformance remains pending, and revision 32 remains the last accepted complete scoped native checkpoint. [Evidence and limits](recordings/r34/README.md).

## Interaction

The resting Launcher has three columns, a centered page name and disabled arrows at either end of the page order. Swipe horizontally to move one page; vertical movement belongs to that page's scroller. Horizontal movement follows the finger and settles over the packet's proposed Launcher duration. Reduced motion settles immediately after release. A touch that starts vertically cannot become a page swipe by turning sideways. Swipe release consumes the old icon press, including an extra egui layout pass. A fresh contact interrupts settling so a header/menu tap can begin immediately.

The top-left Launcher menu opens Search applications, New page and Quick Launch favorites. Page rows select, rename or move a page earlier/later; removal moves its explicit entries to the discovery page and keeps applications installed. The last page cannot be removed. Name editing uses the existing private shell text field/keyboard; Cancel leaves the arrangement untouched. Physical Enter and the touch Enter key accept a valid name. In landscape, Cancel/Save sit in the header above the name field so the keyboard cannot cover them. Invalid names retain the draft and an explanation. Search remains a separate mode across the complete catalog, including apps assigned to other pages; hiding its keyboard retains its query and results. Physical typing from a resting page enters Search. Revision 37 extends that mode into [Just Type](JUST_TYPE.md) with local results and explicitly selected external actions.

Hold an icon to start the existing organization gesture. Move over a page cell to preview placement, or pause near a horizontal edge to preview an adjacent page. Only releasing on a valid destination changes settings. Once an icon has deliberately moved, returning near its original press position remains a moved gesture, including after crossing onto another page. The edge preview alone never persists page selection or placement. Rotation, a second contact, protection, changed catalog/settings, a modal overlay or leaving Launcher cancels the original gesture. A favorite remains a reference to the same desktop ID, independent of its page. Dropping onto the transient Quick Launch tray retains existing favorite add/reorder/full/fixed-position behavior. Unavailable catalog entries may be arranged on pages but cannot become new favorites. The ordinary Launcher has no persistent tray.

The edge band (24 logical units), 600 ms edge dwell, axis ratio and swipe/flick thresholds are proposed tuning values. They need physical-device calibration; they are not measurements of historical webOS behavior. The 58-unit role artwork, 14-unit labels and maximum two label lines follow the packet. Revision-37 Just Type uses smaller icons and one-line labels in compact keyboard-visible landscape results, leaving room for settings/content rows. Native PNG/SVG icon resolution is implemented below; remaining formats and live refresh stay open.

## Identity and persistence

Each page has an immutable numeric ID, a trimmed 1–64 character name and an ordered list of desktop IDs. Names can repeat. The initial Applications page is the discovery inbox; renaming or reordering it does not change its identity. Newly discovered or unassigned catalog entries appear there automatically. Removing the inbox designates the first remaining page as the inbox. Missing desktop IDs remain in their saved slots so temporary removal or an upgrade does not erase the arrangement. A real page move removes the identity from every other page and preserves absent entries. Page order, selected page, inbox identity and a monotonic next ID are saved together.

There are at most 32 pages and 512 explicitly assigned desktop IDs, with a 16 KiB aggregate string budget. Names reject control characters; desktop IDs share the existing Quick Launch validation. Edits validate a candidate before replacing live settings, so an invalid or oversized change cannot partially mutate the arrangement.

Preferences advance to schema 4. Schemas 1–3 migrate in memory without an eager write. The existing worker merges Launcher, favorite, display and notification changes and atomically replaces the private settings file only on a real change. Unknown, mixed, invalid, oversized or unsafe files retain the existing preservation/error behavior. A revision-32 process does not understand schema 4 and must preserve rather than overwrite it. Native QA and package rollback must restore the exact original preference bytes/ownership/mode, not ask the old binary to downgrade them.

Vertical offsets are independent egui session state per page, not durable preferences. Name drafts, menus, drag previews and swipe animation are ephemeral. Ordinary unlocked diagnostics expose saved page state and whether name editing is active, but omit the draft. Protected diagnostics retain their existing restricted schema.

## Native artwork foundation

Original Nocturne role artwork remains authoritative. Other visible application tiles and Quick Launch favorites can request their desktop entry's PNG/SVG icon. The lifted icon uses the same cached image. File lookup and decoding run on a dedicated Rust worker; UI evaluation only requests an application identity or uploads a completed raster. An ignored, duplicate or unavailable request cannot change navigation, menus or text focus. Artwork completion does not change the gesture's scene identity, so an active hold survives it.

Lookup defaults to Adwaita, with a session-start `TAROT_ICON_THEME` override. It searches legacy user icons, XDG user/system icon roots, inherited themes and hicolor, then unthemed icons/pixmaps. Theme directories account for nominal size, scale, fixed/scalable/threshold ranges and nearest-size selection. Theme metadata is cached for the session, with bounded inheritance and cycle detection. Absolute PNG/SVG paths work; relative path traversal is rejected. A session restart is required after catalog, icon or theme changes.

The worker limits requests to 32 outstanding, entries to 256 and completed CPU raster data to 16 MiB, evicting completed entries in arrival order. Missing/invalid files are cached as misses. GPU copies are released when their raster leaves the model; those textures, retained frame references and decoder scratch memory are additional to the CPU cache budget. Rasters preserve aspect ratio/alpha and use the 58-point Launcher target at the output's initial integer scale, capped at 256 pixels. Files are regular-file checked and capped at 1 MiB; metadata at 256 KiB. PNG source area is limited to four megapixels before allocation. SVG markup is capped at 10,000 opening brackets. These are resource guards, not a hostile-document sandbox or a whole-process memory guarantee.

SVG uses pinned resvg/usvg 0.48.1 with Rust text shaping and bundled Lato. SVGZ, system-font scanning and imported images—including embedded data URLs—are disabled. An import request rejects the icon rather than displaying incomplete artwork. XPM, imported-image SVGs and unsupported formats currently use the existing fallback. This is an explicit subset of the [freedesktop icon-theme format requirements](https://specifications.freedesktop.org/icon-theme/latest/); full format conformance, live catalog/theme refresh and runtime scale changes remain open. The APK installs the introduced dependencies' original license notices.

`tests/native_icons_replay.py` checks inherited/hicolor/absolute SVG, scale-specific PNG, rejected imports/misses, lifted artwork and saved favorite pixels on private displays at scales 1 and 2. `tests/phone_native_icons_replay.py` adds installed-session touch, themed Calculator lookup, orientation, PAM and restart support through the canonical phone harness. Native acceptance is recorded separately from source implementation and host results.

## First native attempt

Signed revision 33 passes package/signature audits and real protected startup/PAM, creation, same-page reorder and an immediate menu interruption. Its first cross-page placement fails when the destination is near the original press coordinates: the stationary-hold guard checks final displacement and discards the otherwise valid moved drop. The same sequence fails in the private rendered desktop replay and in a deterministic egui regression. Original evidence is retained privately. The controller also encounters an exit/cleanup race; separate recovery restores the exact original settings/fixture state and normal Tarot, with independent normal-session and Panfrost audits passing.

Revision 34 retains movement history for the gesture and makes the controller tolerate a verified exiting zombie before waiting for the greeter. It passes the unchanged native page replay and saved restart. A separate broader run fails the browser text check on repeat 19; that input failure remains open and does not change the scoped page results. Revision 32 remains the last accepted complete native checkpoint. [Scope and identities](recordings/r34/README.md).
